# Quote PDF retrieval / immutable storage — independent review package (B)

Basis: GitHub main `d7a600c27277fa5cc2498e58e9f053581e48c8bf`, production Supabase `ljgbpbymdkrjcnezaqno` read-only audit on 2026-11-10. **Production not modified**.

## Confirmed
- `quotes_select`: customer, HQ, or currently assigned dealer.
- `quote_documents_select`: customer or HQ only; assigned dealer sees no metadata. Both quote-documents and contract-documents Storage buckets are private; no client Storage SELECT policy for quote-documents.
- PDF GET route: selected existing metadata using user RLS; when missing/inaccessible it re-renders; formerly suppressed save errors.
- `saveQuoteDocument` formerly uploaded `quotes/{quoteId}.pdf` with `upsert: true`, then inserted new metadata row, without uniqueness.
- Production: 11 metadata rows for 7 quote IDs, 3 quote IDs have repeated metadata (4 extra rows); 7 objects in Storage. Cannot infer historical PDF hashes/bytes from metadata alone. No automatic deletion or repair.

## Changes proposed in this branch
- App fails closed on recorded PDF download error, first-save error or Storage object conflict; no PDF bytes returned from a failed save.
- Storage first-creation is `upsert: false` and metadata checked with a server-only service role before upload. Existing file never overwritten through this path.
- `regenerate=1` disabled with HTTP 409; administration's unsafe `PDF再生成` link removed. For changes to issued documents use a new Quote Revision.
- LocalStore mirrors read-only-after-first-write semantics.
- `quote-pdf-rls.sql` is review-only migration **proposal**, outside the migrations folder until generated by Supabase CLI. Grant read-only `quote_documents` SELECT to authenticated customer/HQ/directly assigned sales dealer, not all quote readers; storage stays private and server download still occurs after app/DB authorization. Revoke excessive direct table DML grants from anon/authenticated.

## Preflight, deployment and remaining risk
- No backfill, DML cleanup, object rewrite or PDF regeneration is included. Preserve all existing objects and metadata for review.
- Before applying the review SQL, run `supabase migration new`, place it in the generated file, pin main HEAD + linked project + actual applied and pending migrations, dry-run the exact sequence, verify backups/PITR, and independently review.
- Storage and Postgres operations cannot form one atomic transaction. An upload that succeeds but whose metadata insert fails leaves an orphan; the new code fails closed on subsequent requests rather than overwriting. A fully transactional publishing workflow is a **separate design decision**.
- Existing duplicates prevent adding a UNIQUE(quote_id) constraint without reviewed data migration. **No unapproved cleanup.**
- No production user tokens used and no live HTTP write or integration testing performed.
