# v2.5 の価格への切り替え（スイッチ）の前の確認

シミュレーター・保存した仕様・見積依頼の金額を、公開中の v2.5 の標準見積の売価に切り替える前に確かめることと、切り替え・戻し方の手順です（2026-11-02 作成）。切り替えは千の風の承認の後に、本部が管理画面（見積書管理 ＞ 標準見積）のスイッチで行います。

## 1. 本番に入っていること（承認をいただいてから適用）

| 順 | 内容 | migration |
|---|---|---|
| 1 | v2.5 の一式（原価の Version・計算ルール・標準見積の v2.5・原価の初期取り込み・シミュレーターの v2.5 の売価・旧価格の列の保護） | `20261016200000` 〜 `20261030100000`（6 本） |
| 2 | 位置・用途ごとの選択枠と窓タイプ（S1） | `20261102100000` |
| 3 | v2.5 の見積の第 2 版以降（D1） | `20261102120000` |
| 4 | Web 以外の案件の v2.5 の見積（D1c） | `20261102130000` |
| 5 | 案件の画面のプランボードの位置ごとの表示（S2b） | `20261102140000` |

- migration はタイムスタンプの順に適用する。問い合わせの手動分類（#603・`20261101140000`）は内容は v2.5 と独立だが、v2.5 の一式より先に単独で適用しない（先に入れると v2.5 の migration の番号を付け替えることになる）。v2.5 の一式と一緒に適用すれば順に入る
- 代理店・総代理店の拡張（#502〜#506・`20261016120000`〜）は v2.5 より前の番号のため、再開するときに番号を v2.5 の後へ付け替える
- 適用の各回の手順：GitHub の main・関係する PR と、本番の migration の履歴・未適用の一覧を確かめ直す → preflight（読み取りだけ）→ マージ → dry-run（対象が想定どおりか）→ 直前の日次バックアップの時刻を確かめる（PITR は使っていない）→ 本番適用 → postflight → Security Advisor → 本番画面の確認。dry-run の対象や preflight の結果が想定と違えば適用せずに止める
- アプリは main のマージで本番に出る。S1 は DB を先に（商品の新しい列を読むため）、C1b はアプリを先に出す（旧価格の列を読まない画面にしてから列を閉じる）

## 2. 千の風側の準備（スイッチの前）

1. 採用する標準商品を商品台帳に登録し、本部の標準原価・選択肢の標準原価調整額を入れる（原価の無い商品は売価を出せない）
2. シミュレーターで選べるすべての仕様（モデル・用途・サイズ・防火）の標準見積に、v2.5 の版を公開する
   - 選択枠の決まり：外壁は数量 4（面）、それ以外は数量 1、1 つだけ選べるカテゴリーはカテゴリー単位の枠を 1 つ。位置・用途の枠（サッシの掃出し窓など）は位置ごとに 1 つ
   - 販売停止・廃番の商品を標準構成に入れない。本体に価格未確定（別途見積）の明細を残さない（「本体価格計」に使えないため）
3. 不要な標準見積は無効にする（公開した版の無い有効な標準見積があると切り替えられない）

## 3. DB の確認（読み取りだけ・集計だけ）

`scripts/db-rehearsal/preflight-v25-switch.sql` を流し、`ready_for_switch` が true であることを確かめる。true でなければ切り替えない。

| 項目 | 期待 | 意味 |
|---|---|---|
| `masters_without_published` | 0 | 公開した版の無い有効な標準見積 |
| `masters_published_not_v25` | 0 | 公開中の版が v2.5 でない有効な標準見積（スイッチの関数も止める） |
| `v25_slot_rule_issue_masters` | 0 | 選択枠の決まりに合わない版（スイッチの関数も止める） |
| `v25_base_por_masters` | 0 | 本体に価格未確定の明細がある版 |
| `v25_stopped_product_masters` | 0 | 標準構成に販売停止・廃番の商品がある版 |
| `legacy_price_readable_by_users` | false | 旧価格の列（本部商品の原価）がログインした利用者から読めない（C1b） |
| `standard_quote_drafts_applied` | true | D1c まで適用済み |
| `switch_enabled` | false | まだ切り替えていない |
| `v25_quotes` | 0 | v2.5 の見積はまだ無い |
| `v25_masters_with_newer_costs` | 参考 | 公開の後に原価が改定された商品のある版（版の売価は公開の時の原価のまま。新しい原価にするなら新しい版を公開する）。止める条件ではない |

公開した v2.5 の版の原価がそろっていることは DB の制約が保証します。migration が足りないときは、列・関数が無いためエラーで止まります（＝まだ切り替えられない）。

## 4. 画面の確認

**切り替えの前**（お客様の画面は変わらない）

- 標準見積の Excel 風の画面で、各仕様の v2.5 の版の合計（税込）を確かめる
- 「標準見積から見積書を作成」（Web 以外の案件）は、本番では確認のためだけに作らない（案件と下書きが残るため）。v2.5 の版から作った下書きの合計が版の合計と同じことは実 DB の検査（D1c）で確かめてある。本番では、最初の実際の案件で下書きの合計を版の合計と見比べる

**切り替えの直後**（お客様の少ない時間帯に。問題があればすぐ戻す）

1. シミュレーター：仕様ごとに、標準構成のままの合計が公開した版の合計と同じ。位置の枠（サッシなど）を選び替えると差額が出る
2. 商品一覧・商品ページの「本体価格計（本体一式＋諸費用・税別）〜」が v2.5 の本体の合計の最小になっている
3. プランの保存・再表示で金額が変わらない
4. 見積依頼（第 1 版）の金額がシミュレーターと同じ。案件の画面で見積に版が固定されている
5. 担当の代理店で「見積内容を更新（v2.5）」を開き、商品を足す・別途見積の行に金額を入れる・0円確定・対象外で第 2 版を発行できる。合計の試算と発行後の金額が同じ。千円未満の切り捨てが無い
6. 見積書（PDF）の明細・合計が画面と同じ

## 5. 戻し方

- 同じ画面のスイッチで「これまでの計算に戻す」。シミュレーター・これからの保存・見積依頼はこれまでの価格に戻る
- 切り替えている間に発行した v2.5 の見積は、版を固定しているので金額は変わらない。第 2 版以降も v2.5 の決まりで発行する（スイッチに関係なく）
- 発行済みの見積・保存済みの仕様の金額は、戻しても変わらない（次に保存・見積依頼したときに計算する）

## 6. 先方に確認していただくこと（今の既定で作ってあるもの）

- D1：商品台帳の商品の単価は v2.5 の売価（担当者は変えない）／第 2 版以降は見積依頼のときの版／新しく足した商品の原価は足した時点の Version／千円未満の切り捨てなし（2026-11-04 の先方回答 A-2 ①〜④で承認）
- 経費：2026-11-04 の先方回答 A-2 ⑥で、標準見積・案件見積とも「率で自動」と「金額を手動」を選べるようにする（手動の額は通常の再計算で上書きしない・調整額とは別）。今の v2.5 は率だけなので、別の migration で足す（スイッチ ON の前）
- D1c：v2.5 の版の manual の行（売価だけを決めた選択枠・工事費などの明細）は原価が無い。2026-11-04 の先方回答（A-2 ⑤）で「原価＝売価」は未承認のため、manual の行を含む版からは Web 以外の見積の下書きを作らない（原価の扱いは提案のうえ別の migration で反映する。スイッチ ON の前に済ませる）
