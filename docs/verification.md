### 確かめたこと

- **DB の保存境界（`runtime-product-lifecycle.sql`）**：新しい選択（登録済み・非表示・取扱終了・下書き）、保存済みの明細の保持（同じまま・削除・数量を減らすは可、選択肢の変更・数量を増やす・消してから足し直す・別の面へ足すは不可）、外壁 4 面、複製、見積依頼、見積 Draft（行キー・数量・別行・置き換え）、新しい版での引き継ぎ（元の版と同じ明細だけ）、見積の発行、標準見積（下書きの保持・選択肢・公開）、Excel 標準の基準商品、取扱終了にできない参照、状態の変更の決まり、権限（直接の書き込み・一時領域の部品を呼べない）
- **同時実行（`runtime-product-lifecycle-concurrency.mjs`）**：取扱終了と、構成の保存・見積依頼・見積 Draft の保存・見積の発行・状態の変更（非表示・再開・重ねての取扱終了）が同時に来たとき、どちらの順でも、後から進んだ方が確定した状態で判定されること。画面が読んだ版と違う操作（A→B→A を含む）が失敗すること
- **#507 との組み合わせ（PL-66）**：選択肢のある商品が 2 つの構成で、取扱終了の明細を残したまま別の商品の選択肢を変えて保存できる。#507 が無い DB では、選択肢のある商品が 2 つ以上ある構成はそもそも保存できない（本番の既存の不具合）ため、この確認は省略になる
- **単体**：`tests/product-lifecycle.test.ts`（状態と候補）、`tests/product-lifecycle-rules.test.ts`（選択ルール・初期選択・前提商品・標準構成の組み立て）、`tests/product-lifecycle-local-store.test.ts`（ローカル検証モードの保存境界・台帳の操作の版・商品編集で状態を書き換えない）、`tests/product-lifecycle-guards-migration.test.ts`（migration の適用順・権限・既存関数との差分）
- **E2E**：商品台帳から取扱終了・シミュレーター非表示・再開 → 保存済みプランに「取扱終了の商品（保存済みの選択）」と表示 → 取扱終了が残る間は見積依頼できない → 外すと候補から消える → 非表示だけなら見積依頼できる → 依頼済み（Draft 以外）のプランも保存済みの選択のまま表示（後から取扱終了にしても同じ） → 新しいプランの候補に出ない。再開すると表示設定は以前の値のまま

## 2026-10-14 追記：E2E を今の画面に合わせて整理

9〜10 月の画面の作り替え（商品一覧 → 商品詳細の 2 段階、仕様ボタン、案件管理、見積の表形式の編集、
登録済み商品の「変更内容を確認」、フリー商品の新規登録終了 など）に E2E が追従しておらず、
30 件が失敗したままになっていた。業務上の意図は変えずに、今の画面の操作へ書き直した。

| 種別 | コマンド | 結果 |
|---|---|---|
| 型・Lint・単体・ビルド | `npm run verify` | 147 ファイル・1,205 件 passed／Lint エラー 0／ビルド成功 |
| E2E（Playwright・ローカルモード） | `npm run test:e2e` | 56 passed／1 skipped（下記の不具合待ち）／0 failed（約 9 分） |

- 直した不具合：防火仕様を選び直すと「解除できません」と誤った案内が出ていた（入れ替えで外れた項目は通知しない）
- 外したテスト：代理店がフリー商品を登録して見積へ載せる流れ（新規登録が終了したため。一覧と「登録できないこと」は確認している）
- **Wing の「本体のみ」は保存・見積依頼ができなかった。**
  床・壁・天井の断熱が必須カテゴリーのままで、本体のみでは壁・天井の断熱商品（ホテル・住宅・事務所用だけ）を選べず、
  床断熱も設備表に出ないため選べない。本番の `validate_configuration_items` も同じ判定で拒否する（読み取りで確認）。
  先方確認（同日）で「断熱はお客様が選ぶ必須項目ではない」と決まったので、初期データの断熱カテゴリーを必須から外し、
  E2E（`e2e/flow.spec.ts` の Wing の本体のみ）も通常のテストに戻した。**本番は管理画面のカテゴリー編集で、
  床断熱・壁断熱・天井断熱の「必ず1つ選ぶ（必須）」を外すと直る**
- **管理画面のカテゴリー保存で「お客様のシミュレーターに表示」が保存されていなかった。**
  保存処理（`saveCategoryAction`）がこのチェックボックスを読んでおらず、どのカテゴリーも保存するたびに表示が OFF になる。
  本番で断熱 3 カテゴリーの必須を外したときに表示も OFF になったため、保存処理を直してから管理画面で表示を戻す
  （DB 側の保存・見積の検査はこの項目を見ないので、保存や金額への影響はない。単体テスト `tests/admin-category-save.test.ts`）
- 操作マニュアル（`lib/manual/content.ts`）は、作り替え前の画面の説明が残っている。先方が現行画面に合わせて整理する

| 洗面器と混合水栓を同時に外すと、洗面器だけ残った | ポップアップの適用が台帳順で、依存されている「洗面器」を先に外そうとして拒否されていた | 解除を先に、依存元から順に処理するよう `applyPicker` を修正（`components/simulator/simulator-app.tsx`） |
| 標準構成なのに外観・平面図が「最も近い画像」表示だった | 外壁ガルバリウムにプレビューキーを付けた一方、画像ルール側のキーを更新していなかった | 外観ルールのキーを `exterior_galva` 込みに修正（`lib/seed/catalog.ts`） |
| `/dealers` に h1 が無かった | `RuleHeading` が常に h2 | 見出しレベルを指定できるようにし、`/dealers` は h1 に |
| 平面図クリック領域のテスト ID が UUID だった | カテゴリー ID をそのまま出力 | カテゴリーコードに変更（その後クリック領域自体を撤去） |
| マイグレーション未適用の DB にアプリだけ配信すると全ページ 500 | `preview_hotspots` 不在をエラーとして扱っていた | `lib/data/schema-compat.ts` で旧スキーマを既定値に寄せる |
| 本体のみの構成で見積依頼すると内装が必須だと言われて弾かれた | 見積作成側の検証に注文範囲を渡していなかった | `createQuoteFromConfiguration` と SQL の `validate_configuration_items` に `finish_level` を渡す |
| 高断熱仕様が「スマートロック・鍵」に入っており、本体のみでは選べなかった | 台帳上の分類が実態と合っていなかった | 新設の「断熱仕様」カテゴリー（本体のみから選択可）へ移動 |
| 担当代理店が自分の見積を開けず 404 になった | SQL の RLS は許可していたが、ローカル実装の `getQuote` が顧客本人と管理者しか通していなかった | `LocalStore.getQuote` に担当代理店の判定を追加 |

## 全画面の一括点検（2026-08-23）

`e2e/audit.spec.ts` が公開 17 ページ・会員 4 ページ・管理 14 ページを PC(1440) と SP(390) で開き、
横スクロール／ビューポートはみ出し／h1 の有無／alt 欠落／画像の読み込み失敗／名前のない操作要素を機械的に洗う。
`e2e/audit2.spec.ts` はリンク切れ・詳細画面・noindex・入力エラー時の表示・ポップアップ・SP の代理店入力を見る。

### 見つけて直したもの

| 症状 | 原因 | 対応 |
|---|---|---|
| `/news` `/contact` `/sct` `/privacy` に h1 がない | `RuleHeading` の既定が h2 | 4 ページを `as="h1"` に |
| SP で代理店の別途工事入力画面が 384px 横スクロール | grid の子が既定 `min-width:auto` で、44rem の表に押し広げられていた | 子に `min-w-0`、トラックを `minmax(0,1fr)` に |
| SP で保存仕様の詳細が 272px 横スクロール | 同上（40rem の表） | 同上 |
| オプションカテゴリー画面の説明が旧 UI のまま | シミュレーター改修時の取り残し | 文言を更新 |

### 誤検知として除外したもの

横スクロール領域（管理メニュー・広い表・カルーセル）や `overflow:hidden` の内側にある要素は、
ビューポートより広くても設計どおりなので検出対象から外した（祖先の `overflow-x` を見て判定）。
最終的に**全ページで横スクロール 0px・指摘なし**。
