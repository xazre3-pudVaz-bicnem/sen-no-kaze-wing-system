# 電子契約（GMOサイン）の設定と運用

当面はサイプレスの GMOサインアカウントで運用を試し、問題がなければ技術の杜のアカウントへ切り替えます。切り替えは環境変数の差し替えと通知先の再登録だけで済み、コードの変更は不要です。

## 流れ

1. お客様が確定見積を承諾する（マイページ）
2. 本部が案件の「契約書類」タブで、署名者の氏名とメールアドレスを確認して「GMOサインで契約書を送信する」を押す
3. GMOサインから、お客様へ署名依頼のメールが届く。お客様は GMOサインの画面で署名する
4. 署名が完了すると、GMOサインからこのシステムへ通知が届く。システムは署名済みの PDF を GMOサインから取得して保存し、状態を「締結済み」にする
5. お客様はマイページの見積詳細から、本部は契約書類タブから、締結済みの契約書（PDF）を開ける

- 契約書の本文（条文）は、GMOサイン上の契約書テンプレートで本部が管理します。システムは条文を持ちません
- 契約金額は、送信した時点の承諾済み見積の税込合計です。見積の金額・状態は変わりません
- 送信に失敗したときは「送信失敗」になり、もう一度送信できます。送信後に取り消す場合は、システムで「この契約を取り消す」を押し、GMOサイン上の封筒は GMOサインの画面で取り消します

## GMOサイン側の準備

### 1. API の利用契約

- Web API はスタンダードプラン以上で使えます。API 仕様書の開示と検証環境の提供は別料金です（[GMOサイン Web API](https://www.gmosign.com/app-connect/api/)）
- GMOサインのサポートから、**顧客ID** と **APIシークレットキー** を発行してもらいます
- このシステムは、GMOサインが公開している連携定義（Power Automate コネクタ）と同じ API（`https://api.gmo-exapi.net/gmosign`、Basic 認証）を使います。発行時に、この API を使える契約かどうかを確認してください

### 2. 契約書テンプレート

GMOサインの画面で、工事請負契約書のテンプレートを作ります。

- 自社の署名者（契約印）：テンプレートに登録します（システムからはテンプレートの署名者を使う指定で送ります）
- 取引先の署名者：送信時にシステムがお客様の氏名・メールアドレスを指定します
- 差し込み項目：次の名前で作ります（**名前は完全に一致させる**）

| 差し込み項目名 | 入る値 |
| --- | --- |
| 見積番号 | 承諾済み見積の見積番号 |
| お客様名 | 見積のお客様名 |
| 会社名 | 見積の会社名（無ければ空欄） |
| 商品 | 機種名 |
| 税抜金額 | 例：4,500,000円 |
| 消費税 | 例：450,000円 |
| 契約金額（税込） | 例：4,950,000円 |
| 見積発行日 | 例：2026年10月13日 |

作ったテンプレートの ID を控えます。

## システム側の設定

Vercel の環境変数（Production）に次を設定し、再デプロイします。

| 変数 | 内容 |
| --- | --- |
| `GMOSIGN_CUSTOMER_ID` | 顧客ID |
| `GMOSIGN_SECRET_KEY` | APIシークレットキー |
| `GMOSIGN_TEMPLATE_ID` | 契約書テンプレートの ID |
| `GMOSIGN_WEBHOOK_TOKEN` | 通知先 URL に付ける推測できない文字列（例：`openssl rand -hex 32` の出力） |
| `GMOSIGN_API_BASE_URL`（任意） | 検証環境で試すときの接続先 |
| `GMOSIGN_SENDER_NAME`（任意） | 送信者名 |

4 つの必須の値がそろうまで、管理画面は「接続設定が未完了」と表示し、送信できません。

### 署名完了の通知先を登録する

環境変数を `.env.local` にも置いたうえで、1 回だけ実行します。

```sh
node scripts/gmosign-register-webhook.ts --events <通知するイベント>
```

- 通知先は `https://www.sen-no-kaze.com/api/webhooks/gmosign?token=<GMOSIGN_WEBHOOK_TOKEN>` です
- `--events` の値は、GMOサインの API 仕様書の `envelopeEvents` で確認してください（署名完了を通知する値）
- 通知はトークンが一致するものだけ受け付けます。さらに、通知の内容は信用せず、署名済みの PDF をこちらの資格情報で GMOサインから取得できたときだけ「締結済み」にします

## 検証環境で確認すること

GMOサインの公開資料だけでは確定できない点です。検証環境（または本番アカウントの試験送信）で確認してください。

1. テンプレート送信で、自社署名者を「テンプレートの署名者を使う」指定（`use_template: 1`）で送れるか
2. 署名完了の通知に入る文書 ID（`documentId`）と、送信時の応答の文書 ID（`control_number`）が同じものか
3. 文書の取得（`download_type=2`・`operation=1`）で、署名済みの PDF が返るか
4. `envelopeEvents` に指定する値

違いがあった場合の修正箇所は `lib/integrations/gmosign.ts` だけです。

## 本番での前提

- 電子契約の表（`contracts`）と保存先（`contract-documents`）は、未適用の migration `20261013150000` で作られます。本番 DB へ migration を適用するまで、管理画面の電子契約は使えません
- 締結済みの PDF は非公開の保存先に置き、お客様本人と本部だけが開けます
