## 商品の標準原価の Version（2026-10-16・v2.5 Phase 1 の PR-A1）

商品の標準原価（税別）と、バリエーション（選択肢）の標準原価調整額を、上書きではなく Version（変えられない履歴）で持ちます（`20261016200000_option_standard_cost_versions.sql`）。本番への適用は、Phase 1 では行いません（別途の承認後）。

- 変更・訂正は新しい Version を作り、それまでの Version は値を変えずに「閉じる」だけです。作った Version は DB の管理者でも書き換え・削除できません（トリガーで拒否）
- 同じ商品・同じ選択肢の「現在の Version」は常に 1 つです（部分一意 index）
- 本部商品基準原価の画面・Server Action・`set_option_hq_standard_cost` の呼び方は変えていません。RPC の中で新しい Version を作り、`option_hq_standard_costs` は現在の Version の写し（どの Version かを `current_version_id` で持つ）として同じ transaction で更新します。既存の行があれば Version 1 として移します（本番は 0 行）
- 調整額はプラス・0・マイナスを持てます（±1 億円まで）。設定できるのは global admin と本部の owner・admin、読めるのはそれに本部の editor を加えた人だけで、総代理店・代理店・お客様は読めません（本部商品基準原価と同じ権限）
- 原価・調整額の履歴がある商品と選択肢は削除できません（FK RESTRICT。販売停止・廃番で扱う）
- 本部標準原価は本部商品だけに持ちます（2026-10-29 先方の回答）。いまの作りで本部商品の外にある旧フリー商品（代理店が登録した商品）には、本部でも商品の原価・選択肢の調整額を設定できません（判定は `option_is_hq_cost_product`。所有組織の区分を足すときはこの関数で本部商品の外にする）
- 標準見積・シミュレーター・見積からの Version の固定（pin）は後続の PR で行います。この PR では金額の計算・表示は変えていません

### こちらで判断したこと（確認したい点）

- **「適用後の標準原価は 0 円未満にしない」の確かめ方**：選択項目ごとに最も低い（マイナスの）調整額を足した下限で確かめます。必須・任意や選択肢の公開状態は後から変わるため、どの選び方でも下回らない下限にしています。そのため、必須項目のプラスの調整額で相殺される組み合わせ（例：原価 0 円の商品に「必須のサイズ +1 万円」と「任意の部材 −3 千円」）も拒否し、v2.5 の条件より厳しい側に倒しています。相殺を認める必要があれば、必須項目の扱いを決めたうえで変えます
- 商品の原価が未設定の間は、調整額だけを先に設定できます。原価を設定するときに上の下限で確かめます

## 計算ルール・税ルールの Version と正式計算（2026-10-16・v2.5 Phase 1 の PR-A2）

正式計算の順序と切り捨ての境界、税の方式を Version で持ち、DB と TypeScript に同じ計算を置きました（`20261016210000_pricing_rule_versions.sql`・`lib/domain/pricing-v25.ts`）。既存の標準見積・シミュレーター・見積の計算は変えていません（呼び出し側への組み込みは後続の PR）。本番への適用は、Phase 1 では行いません。

- 計算ルール Version：式（`v2.5`）・切り捨て（`trunc`）・経費を計算する区分・auto（販売費率・掛率の自動計算）を使える区分。初期は `CALC-V25-1`（経費・auto とも本体・内外装・オプション）
- **別途工事には販売費・経費・掛率を掛けません**（2026-10-19 先方の確定方針）。別途工事の明細は、担当が決めた税別売価の manual か、別途見積（POR）だけです（auto は正式計算で拒否）。今の本番の見積・標準見積（v2.5 以前の計算）も別途工事に経費を掛けておらず、同じ扱いです。計算方式を変えるときは新しい計算ルール Version で行い、発行済みの見積・Snapshot は変えません
- 税ルール Version：全額課税・単一税率。初期は `TAX-10-1`（10%）
- どちらも作った後は変えられず（トリガー）、現在有効は 1 つだけです。過去の Version も、固定した見積の再計算に使えます。新しい Version は migration で、現在の Version を閉じてから作ります（画面からの変更はまだありません）
- 読めるのは global admin と本部の editor 以上（標準見積と同じ）。正式計算の関数は API のどの role からも直接は実行できません（後続の RPC の中から使う）
- 計算の決まり
  - auto：`trunc((商品標準原価 + 調整額) × 販売費率)` → `trunc(× 掛率)` → `trunc(× 数量)`。選択状態の原価が 0 円未満なら計算しません
  - manual：`trunc(売価単価 × 数量)`（販売費・掛率は掛けない）
  - por：0 円にせず、その区分の小計・経費と、合計・税をすべて未確定（null）にします。確定している明細だけの合計は表示用に別に返します
  - 区分経費 = `trunc(区分小計 × 経費率)`（計算ルールの経費対象区分だけ。別途工事は対象外）、調整額は整数円をそのまま加減算（調整後 0 円以上）、税 = `trunc(調整後税別額 × 税率)`
  - 1,000 円未満の切り捨てはしません（v2.5 の宣言した境界だけで切り捨てる）
- 精度：率は小数 4 桁まで、数量は小数 4 桁まで（末尾の 0 は数えない）、金額は整数円。DB は numeric、TypeScript は BigInt の固定小数で計算し、浮動小数点は使いません。扱える金額は ±999,999,999,999 円までで、超えたら計算しません
- DB と TypeScript の一致：手で検算したテストベクトル（`tests/fixtures/pricing-v25-vectors.json`）を両方で確かめ、さらに実 DB の検査で決まった種のランダムな入力 400 件の結果（エラーの種類を含む）を突き合わせます

- 100V／200V、専用回路、契約容量などの自動判定はしません。構造化が必要になったら、空調専用ではなく、IH・給湯器などにも使える汎用の商品仕様として別に設計します

## 商品の取扱終了・シミュレーター表示（2026-10-15・PR #500）

先方の最終指示書 v2（2026-10-15）に合わせて、商品台帳に取扱終了とシミュレーター表示の設定を足しました。

| 状態 | DB の値 | 見積・標準見積で新しく選ぶ | シミュレーターで新しく選ぶ | 保存済みの明細・発行済みの見積 |
|---|---|---|---|---|
| 下書き | `status='draft'` | できない | できない | （下書きは保存できない） |
| 登録済み | 公開中・`archived_at` なし | できる | 表示設定が ON のときだけ | そのまま |
| 取扱終了 | 公開中・`archived_at` あり | できない | できない | 残す（台帳でも見られる・編集できる） |

- **シミュレーター表示 OFF は見積不可ではありません。** シミュレーターの新しい選択肢から外すだけで、見積・標準見積では選べます。見積依頼・発行も止めません
- **保存済みの明細は、保存前の DB の状態と照合して残せる範囲を決めます。** 同じ明細のまま保存し直す・削除する・数量を減らすは残せます。数量を増やす・別の明細として足す・一度消してから足し直す・別の商品から置き換える・選択肢を変える・別の面に足す・複製は、新しく選ぶ扱いで止めます
- **取扱終了の商品が残っている構成からは、見積依頼・見積の発行・標準見積の公開ができません。** 取扱の再開を待つか、別の商品へ替えてもらいます
- 見積の新しい版は、元の版（DB の発行済み明細）と同じ明細・数量以下なら、取扱終了の商品も引き継げます。発行はできません
- 商品 ID を持たない明細（標準見積・本体 Revision から写した行、自由入力の行）は判定しません。品名などから商品を推測しません
- 判定は画面だけでなく DB のトリガー（`20261015113000_product_lifecycle_guards.sql`）で、保存と同じトランザクションの中で行います。取扱終了の操作と保存が同時に来ても、どちらかが待ってから確定した状態で判定します
- 台帳の操作（取扱終了・再開・シミュレーターに表示する／しない）は、画面が読んだ版（`updated_at`）のときだけ反映します。古い画面からの操作は失敗にします。権限は従来の商品台帳の編集権限のままです（#502 の未確定事項はここで変えていません）
- 台帳の操作は、DB の migration 2 本（`20261015110000`・`20261015113000`）が適用済みのときだけ出します。片方だけでは出しません
- **実際の商品の取扱終了は別の工程です。** この PR では本番の商品を取扱終了にしていません

## 見積の金額と、標準見積から作る見積（2026-10-13・PR H）

統合版依頼書 §6-2・§8 に合わせて、見積の金額の決まりを次のとおりにしました。

- **新しい見積下書き・新しい版の明細額は trunc（0 方向切り捨て）**です。手入力の見積も同じです。
  - これまでは四捨五入（round）でした。違いが出るのは、数量が小数の行だけです（例：2.5 m × 2,001 円は、これまで 5,003 円、これから 5,002 円）
  - 発行済みの見積はそのまま変えません。旧 round で発行した版から第 2 版を作ると、第 2 版は trunc で計算し直します
- **公開中の標準見積から見積を作れます**（案件管理の「標準見積から作成」、または標準見積の一覧の「見積書を作成」）。作成・編集・発行は本部だけです。
  - 下書きには、標準見積の率（販売費率・経費率・掛率）・調整額・明細を写します。本体は、標準見積が固定した本体 Revision の明細から作ります
  - 経費（本体諸費用・内外装工事経費・オプション諸費用・別途工事経費）は金額を写しません。経費率を写して、見積自身の区分小計から計算し直します。率や明細を見積側で変えても、標準見積には反映しません
  - 価格未確定（POR）の行は、下書きでは使えます。1 行でも残っていると発行できません
  - 第 2 版以降は、直前の発行版の率・明細・元の標準見積 Revision を引き継ぎます。最新の標準見積には追従しません
- 内部原価・率・粗利は、本部だけが読める専用の表に保存します。発行時の値も snapshot として保存します。見積書（quotes / quote_items）・PDF・お客様向けの画面には原価を入れません
- 標準見積（原価・率を含む）を閲覧できるのは本部だけです。代理店向けの経路は、原価を除いた形で後から設計します
- 代理店は、標準見積から作った見積の改訂・発行を現在できません（本部だけ）。代理店の対応範囲は第 2 段階で決めます

## 標準見積の「標準状態の商品」と、売価だけの取得経路（2026-10-13・PR C1）

シミュレーターを新しい標準見積へ切り替える準備です。お客様向けの画面・価格はまだ変わりません。

- **標準状態の商品**は、標準見積の Revision ごとに本部が登録します（標準見積の編集画面の下の欄）。シミュレーターで「標準の選択」とみなす商品です
  - お客様が商品を変えたときの差額は「選んだ商品の価格 − 標準状態の商品の価格」にします（20260915012500 の基盤の設計どおり）
  - 登録できるのは、その仕様でお客様が選べるカテゴリーの公開中の商品だけです。「シミュレーターの標準選択を読み込む」で、現在のシミュレーターの標準選択を下書きに入れられます
  - 価格は、公開時に商品台帳のその時点の価格で確定します。公開後に商品台帳の価格が変わっても、公開済みの標準見積は変わりません
  - 次の Revision へ引き継ぎます。初期登録した 10 件の標準見積には、まだ標準状態の商品がありません（次の Revision で登録します）
- **売価だけの取得経路**（`get_standard_estimate_sale_views`）は、公開中の標準見積を売価だけの形で返します。原価・販売費率・掛率・調整理由・明細の備考は返しません
  - シミュレーターのページがサーバー側（サービスロール）で呼びます。未ログインの利用者・お客様が API から直接呼ぶことはできません
- 標準状態の商品が登録されていない標準見積は、シミュレーターの価格には使いません（切り替えは次の段階で行います）

## シミュレーターと見積依頼の、新しい標準見積への切り替え（2026-10-13・PR C2）

- シミュレーターの価格・保存した仕様の金額・見積依頼の見積は、次の条件をすべて満たすときに新しい標準見積で計算します
  - 標準状態の商品が登録されている
  - 公開中である
  - 機種・用途・防火で 1 件に決まる
- 条件を満たさないとき（本番で初期登録する前、標準状態の商品が未登録、サイズ違いが複数）は、これまでの計算のままです
  - **本番の価格が変わるのは、本番で初期登録し、標準状態の商品を登録して公開したとき**です（初期登録単価の案 A のため、お客様向けの価格は確定資料の Excel の約 1.5 倍になります）
- 計算のしかた
  - 本体：標準見積の売価（本体マスターの原価 × 販売費率 × 掛率）と本体諸費用
  - 内外装・オプション・別途工事：標準見積の明細小計 ＋（選んだ商品の価格 − 標準状態の商品の価格）。経費は区分の明細小計 × 経費率で計算し直します
  - 選んだ商品は商品台帳の現在の価格（バリエーション・外壁 4 面を含む）、標準状態の商品は公開時の価格です。外壁の標準状態は 4 面分として数えます
  - 調整額は標準見積の調整額を使います。旧来の「1,000 円未満切り捨て」はしません。すべての計算境界で切り捨て（trunc）です
- 防火
  - 「防火仕様」を選んでいて防火の標準見積があれば、防火の標準見積で計算します
  - 防火の標準見積が無ければ非防火の標準見積で計算し、防火はこれまでどおり別途見積です
- BOX の「hotel-single」（旧仕様）は、BOX ホテル仕様の標準見積で計算します
- 見積依頼の見積書には、次の行が並びます
  - 本体の内訳（売価）・本体諸費用
  - 標準見積の明細（売価。価格未確定の行は 0 円で「別途お見積り」）
  - 選択商品の変更差額・各区分の経費
  - 外壁の面別の仕様（0 円）
- 見積書の行の合計は、税抜（調整前）と一致します

## お客様のフェーズ2〜3：ログインなしの一時保存・設置予定地と土地（2026-10-14）

  - 保存するのは仕様の選択だけです（商品・色・外壁の面・仕様・設置予定の地域）。**価格は保存せず、開いたときの価格で計算し直します**。台帳から外れた商品は、開いたときに自動で外れます。台帳から外れた色・仕様（選択肢）も外れ、その項目は標準の選択肢に戻ります（保存したプランを開き直すときも同じ）

  - URL から開いたプランは未保存の新しい下書きです。会員登録して保存すると、マイページの新しいプランになります
- **設置予定地・土地（フェーズ3「設置予定地域・土地確認」）**：保存したプランごとに入力します（マイページの「設置予定地・土地の情報を入力する」と、見積依頼の画面の「土地について（任意）」）

  - 読めるのはお客様本人・本部・その案件の担当代理店と製造の担当。書けるのはお客様本人と本部です（担当代理店は現地確認の記録に書きます）。担当は案件画面の「現地確認」タブで見られます

## 案件の進行：代理店の紹介・受付・日程・現地確認（2026-10-13・フローチャート第4版 フェーズ4〜7）

案件は見積依頼（quote_requests）の単位です。案件への関わり方は DB の `case_access()` で判定します。

| 関わり方 | 誰か | できること |
| --- | --- | --- |
| 本部 | 管理者 | すべて |
| 担当代理店 | 案件の現在の見積の担当（dealer_id） | 受付・自分を主担当者にする・日程・現地確認・打合せ記録・本部への相談・写真 |
| 技術検討・製造の担当 | 本部が案件ごとに指定した総代理店 | 技術検討（製造可否・概算コスト）の記録・現地確認の閲覧 |
| お客様 | 見積依頼の本人 | 希望（代理店・打合せの方法・希望日）・日程の選択・資料の送付・進み具合の閲覧 |

- **代理店の紹介ページ**（フェーズ4）：代理店・総代理店は自分の紹介（対応エリア・施工対応・資格・実績）を登録できます。**公開・非公開は本部が決めます**。公開中の代理店だけが、公開ページ（/dealers）の検索と、見積依頼の「相談したい代理店」に出ます
  - 対応エリアは都道府県で指定します。市区町村を書いた都道府県は、その市区町村だけを対象にします
- **見積依頼のときの希望**（フェーズ5）：相談したい代理店（公開中のみ）・打合せの方法・希望日（3 つまで）・日程のご要望。担当代理店の割り当ては、これまでどおり本部が行います（お客様の指定は参考）
- **受付・担当**（フェーズ5〜6）：担当代理店か本部が「受付済み」にすると、お客様へ知らせます。主担当者は本部の担当者か、その案件の担当代理店から選びます（担当でない人へ案件の閲覧を広げない）
- **日程（予約ボード）**（フェーズ6）：担当が候補（1〜5 つ）を送り、お客様がマイページで選びます。合わなければ、お客様は要望を送れます。電話などで決まった日時は、担当がそのまま確定できます。案件をまたいだ一覧は「予約ボード」
- **現地確認**（フェーズ7）：土地・搬入・インフラ・法規・行政の確認内容と測量のメモ・写真を記録し、完了にします。**お客様には中身を見せず、完了したことだけを知らせます**
- **社内の記録**：打合せ記録・本部への相談と回答・総代理店の技術検討（製造可否・概算コスト）。追記だけで書き換えません。お客様には見せません
- **写真・書類**：非公開の保存先（case-files）に置き、見てよい人だけにサーバーが渡します。担当の資料はお客様に見せるかを選べます（初期値は見せない）。お客様が送った資料はお客様にも見えます
- **先方の確認待ちのため作っていないもの**：案件番号の採番（形式）、代理店の見積依頼への回答期限、代理店の担当者ごとのアカウント（組織・所属の正式な運用）

## 案件の進行：見積の修正依頼・書面の契約（2026-10-13・フェーズ9〜10）

- **見積の修正依頼**（フェーズ9「修正したい（再見積へ）」）：お客様は、発行済みの現在の見積に「内容の修正を依頼する」を送れます（同じ見積には対応中の依頼を 1 件まで）。担当代理店・本部へ知らせます
  - 修正依頼は見積の状態を変えません（承諾・辞退はこれまでどおり）。見積を直すときは、これまでどおり新しい版を作って発行し、修正依頼を「対応済み」にします（お客様へ知らせます）
- **書面で締結した契約**（フェーズ10）：電子契約（GMOサイン）に加え、紙の契約書で締結したときは、本部が署名済みの契約書（PDF）を記録できます

  - 契約書は電子契約と同じ非公開の保存先に置き、お客様はマイページの見積詳細から開けます
  - 誤って記録したときは、本部が理由を残して無効にできます（記録は消さず「取り消し」として残る）。その後、記録し直せます
- **先方の確認待ちのため作っていないもの**：着手条件（着手金・入金のタイミング・分割払い）と入金管理

## 案件の進行：製造依頼と個体・工程表・施工の記録（2026-10-13・フェーズ11〜13）

- **製造依頼**（フェーズ11）：担当代理店か本部が、締結済みの契約がある案件の製造依頼を作り（棟数・希望納期・製造仕様のメモ）、本部が指定した製造の担当（総代理店）へ送ります。1 つの案件に有効な製造依頼は 1 つです
  - 送るときに、契約した見積の明細を製造仕様のスナップショットとして残します（品名・数量だけ。価格は写しません）
  - 総代理店が受領 → 製造中 → 出荷、担当代理店が設置まで完了にします。取り消しは本部だけ（理由が必要）
  - 本部は「基幹資材の供給手配」のメモを残せます。全国の製造の進み具合は「製造の進み具合」（/admin/manufacturing）で一覧します
- **個体**：1 棟ごとに作り、製造・検査・出荷（総代理店）と設置・引渡し（担当代理店）の状態と日付を記録します。状態は前へだけ進められます（戻すのは本部だけ）
- **工程表**（フェーズ12）：担当代理店・本部が作ります。総代理店は製造・品質検査・出荷の工程だけ作れます。**お客様へ見せるかは項目ごとに担当代理店・本部が決めます（初期値は見せない）**。見せる工程のメモはお客様にも表示されます
- **施工の記録と写真**（フェーズ13）：搬入・設置・基礎・給排水・電気の進み具合、検査、完了、総代理店の技術支援を記録し、写真を付けます。お客様へ見せるかは記録ごと・写真ごとに決めます
- お客様の「ご依頼の進み具合」には、製造の状態と台数（出荷・設置）、見せる工程と施工の記録だけを表示します（製造仕様・供給手配のメモは見せない）
- **先方の確認待ちのため作っていないもの**：注文番号・個体番号の採番（形式）と QR コードの表示内容。欄は用意してあり、形式が決まれば発行の処理を足します

## 案件の進行：完了確認・是正・引渡し、アフター、災害時提供（2026-10-13・フェーズ14〜15）

- **完成確認**（フェーズ14）：担当代理店か本部が、締結済みの契約がある案件の完成確認を始め（確認日・内容）、お客様へ確認をお願いします。内容はお客様にも表示されます
  - お客様はマイページで「問題ありません」か「気になる点」（1 行に 1 つ、20 件まで）を回答します。気になる点は是正事項になります
  - 是正事項は担当が「是正した」にし、お客様（または担当）が「是正を確認した」にします。確認が済むまで「問題ありません」は選べません
  - 担当も是正事項を足せます。確認済みの後に足したときは、お客様の確認と承諾書の記録を待ちに戻します
- **工事完了承諾書**：署名済みの承諾書を「完了確認・引渡し」の資料として登録し、担当が記録します。**マイページを使わないお客様もいるため、承諾書の記録をお客様の確認（書面）として扱います**。記録した写しは削除できません
  - 承諾書の電子署名（GMOサイン）はテンプレートが先方の準備待ちのため、書面の写しで記録します
- **引渡し**：お客様の確認と承諾書の記録の後に、担当が引渡し日を入れて完了にします。**設置済みの個体だけ**を引渡し済みにします（設置済みでない個体があれば画面で知らせます）。引渡しの後の不具合はアフターで受けます
- **アフター**（フェーズ15：定期点検・問い合わせ・修理）：引渡しの後に、お客様（マイページ）・担当代理店・本部が登録します。担当は状態とお客様への回答を記録します（回答はお客様にも表示）
  - 製造起因のものは、担当か本部が製造の担当（総代理店）へ回します。**総代理店が見られるのは回されたものだけ**で、回答と完了だけ記録できます。完了したものは戻せません（新しい依頼として登録）
  - 一覧は「アフター」（/admin/after-service）
- **保証**：保証の期間・内容は先方の確認待ちのため、保証期限は表示しません（引渡し日は記録します）
- **災害時提供の意思**（フェーズ15）：お客様が引渡しの後に、マイページで承諾・条件付き承諾・不承諾を選びます。いつでも変えられ、変更の履歴は残ります（最新が今の意思）
  - **承諾書の文面は先方が決めます。本部が「災害時提供の承諾書」（/admin/disaster-consent）で文面を登録するまで、お客様には表示しません**。文面は版ごとに残し、お客様は最新の版を読んで回答します
  - お客様の意思は、本部・担当代理店に見え、総代理店には見せません
- **全国ストック台帳**（本部だけ・/admin/stock-ledger）：引渡し済みの個体について、本部が登録状態・稼働状況・所在地・最終点検日・即時提供・輸送・72 時間／7 日の供給可否を判定します
  - 「登録中」にできるのは、お客様の今の意思が承諾か条件付き承諾の個体だけです。お客様が不承諾にしたら、登録を自動で止めます
- **先方の確認待ちのため作っていないもの**：保証の期間・内容、承諾書の文面（災害時提供・工事完了の電子署名テンプレート）、災害時パートナーの管理、供給指揮システムとの連携

## サイトの新価格への切り替えスイッチ（2026-10-13）

先方回答：標準見積の登録・標準状態の商品の設定・未確定商品の確認が進み、本番の画面で最終金額を確認するまで、サイトの新価格へは切り替えない。

- 本部の管理者だけ、標準見積の一覧の「シミュレーターの価格」から、新しい価格のプレビュー（`/simulator/<機種>?preview=standard`）を開けます。プレビュー中は保存・見積依頼はできません
- スイッチを入れられるのは本部だけで、確認のチェックが必要です。切り替え・戻しは監査ログに残ります。**入れるのは先方の最終確認のあと**です

## 注文範囲（2026-08-22 の先方フィードバック）

先方の定義：**本体＝木造躯体に屋根・外壁・サッシ・玄関ドアまでを工場で取り付けた状態**。
お客様はどこまで頼むかを選べる。画面（シミュレーター冒頭のカード）と商品詳細ページに説明を入れている。

| 注文範囲 | 含まれるカテゴリー（`option_categories.finish_level`） |
|---|---|
| 本体のみ（shell・DIY） | 外壁・サッシ・断熱仕様・防火仕様・別途工事 |
| 本体＋設備（equipment） | 上記＋浴室・トイレ・洗面・キッチン・給湯・空調・照明・家具・家電・スマートロック・外構部品・事務所用品 |
| フル装備（full） | 上記＋床材・壁／天井・内部建具・造作工事 |

- 必須カテゴリーの検証は**注文範囲に入っているカテゴリーだけ**に効く。本体のみで内装を要求しない。
- 範囲を狭めると範囲外の選択は自動で外れ、広げると仕様の標準構成から不足分を補う。
- 範囲は `configurations.finish_level` に保存し、発行時に `quotes.finish_level` へスナップショットする（画面・マイページ・管理画面・PDF に表示）。
- 各カテゴリーの範囲は管理画面のカテゴリー編集から変更できる（コード直書きなし）。
- 高断熱仕様（スタイロフォーム90mm）はあとから変更できないため、「スマートロック・鍵」から新設の**断熱仕様**カテゴリーへ移し、本体のみでも選べるようにした。
- **断熱（床・壁・天井）はお客様が選ぶ必須項目にしない（先方確認 2026-10-14）**。断熱材は Base Master 側の「構造・製造に必要な直接原価」に含める整理で、お客様が本体分類表（Matrix）で選ぶ商品ではない。床断熱・壁断熱・天井断熱のカテゴリーは「必須」を外す（本番は管理画面のカテゴリー編集で外す）。必須のままだと、断熱の商品を選べない Wing の「本体のみ」が保存・見積依頼できなかった。具体的な断熱材（床用ミラフォーム 90mm・壁／天井用スタイロフォーム 90mm など）は、この回答では正式仕様として固定しない

## 権限とフリー商品（2026-08-22 の先方フィードバック）

### 権限階層（`profiles.role_code`）

| 権限 | できること |
|---|---|
| 顧客 customer | 見積シミュレーション・保存・見積依頼。管理画面には入れない |
| 代理店・工務店 dealer | 管理画面のうち **商品台帳の閲覧** と **自社フリー商品の登録・編集**。担当見積の別途工事・フリー商品の入力 |
| 総代理店 master_dealer | 上記＋**商品台帳への商品登録・価格編集**（本体・カテゴリー・商品・画像・プレビュー） |

- 判定は SQL 側（`role_rank` / `can_edit_catalog` / `is_dealer` と RLS）とアプリ側（`requireStaff` / `requireCatalogEditor`）の両方で行う。**画面を隠すだけにしない。**
- 管理画面のメニューは権限で出し分ける。代理店には台帳編集・顧客・見積のメニューが出ない。

### フリー商品

代理店・工務店が自分で登録する商品（ベッド・イスなど）。分類「フリー商品」／カテゴリー `free-product`。

- `options.owner_id` に登録者を持ち、代理店は**自分が登録したものだけ**編集できる（RLS とサーバーアクションの両方で制限）
- 見積書では **別途工事の下に「５ フリー商品」** として別枠表示（画面・マイページ・管理画面・PDF）
- **諸費用 15% は乗せない**（技術の杜の商品ではないため）。消費税だけが乗る
- 注文範囲は「本体＋設備」から選択可

### 代理店による確定見積（改訂版）

発行済みの見積は金額を書き換えない設計のため、代理店の入力は**新しい版を発行する**形にしている。

```
顧客が見積依頼
  → 第1版：概算見積（技術の杜の工場生産分。別途工事は「別途」表示）
    → 管理者が担当代理店を割り当てる（/admin/quotes/[id]）
      → 代理店が別途工事・フリー商品を入力して発行
        → 第2版：確定見積（第1版は status=superseded で履歴として残る）
```

- 見積番号は `Q202608-0001` → `Q202608-0001-2` と枝番になる
- 本体価格・オプション価格の明細は親の版からそのまま複製する（技術の杜のスナップショットを崩さない）
- 代理店が触れるのは `installation`（別途工事）と `free`（フリー商品）の明細だけ。SQL 側でも kind を検査している
- 合計は入力後にサーバー側で再計算（千円未満切捨て → 消費税）。クライアントの計算結果は使わない
- 代理店は**自分に割り当てられた見積だけ**閲覧・入力できる（RLS ＋ アプリ側の 二重チェック）
- 顧客のマイページには「第1版・概算見積」「第2版・確定見積」が版として表示され、代理店の申し送りも出る

### エンドユーザー間のフリーマーケットについて

ご提案いただきましたが、**第一段階では見送り**を推奨しています。個人間売買になると特定商取引法の表示義務、決済と返金、
トラブル対応、中古品を扱う場合の古物営業法まで関わり、Wing の見積システムとは別の仕組みが必要になるためです。
